This page records supplementary places where HIMR material may be found. It is a
**discovery inventory**, not a declaration that every account belongs to Daniel or
that every copy is complete and authentic. A working link establishes that the page
was reachable when checked; it does not establish who controlled it when an item was
published.

<Aside type="caution" title="“Inactive” and “unreachable” are different states">
  Several supplied links were described as inactive, but their endpoints still
  responded on 27 August 2026. The table below records the observed web state
  rather than inferring recent posting activity. Mutable counts and profile text
  must be captured again before they are relied upon later.
</Aside>

## Reddit archive search

The [r/HIMRFAM search for “Archive”](https://www.reddit.com/r/HIMRFAM/search/?q=Archive)
is a useful, continuously changing discovery route. A current result also points to a
[community archive inventory post](https://www.reddit.com/r/HIMRFAM/comments/1q2sk8g/new_himr_archive_update_and_reminder_of_other/).
Neither the search page nor the post is a fixed manifest. Before ingesting a result,
the project should preserve the post permalink, direct media URL, platform ID where
available, retrieval time, bytes, and checksum. Assertions in post titles and
comments remain community claims unless the linked media supports them.

The January 2026 inventory specifically points to four older source families: the
[`69999`](https://archive.org/details/69999) pre-September-2020 collection,
[`699992`](https://archive.org/details/699992) covering a stated September 2020–August
2023 range, the [`28766`](https://archive.org/details/28766) 2017–2019 livestream-clip
collection, and the 722 GB torrent. Those date ranges and completeness descriptions
come from the Reddit archivist and are treated as collection labels until reconciled
file by file.

In a comment on that inventory, the torrent uploader also supplied a
[731-URL Archive.org complement list](https://files.catbox.moe/f5yr6k.txt), described
as files present in the public Archive.org collections but absent from the torrent.
The project retained the list and reconciled its URLs against the sealed provider
snapshots: 510 already named provider-file sources and 221 older URL hints had exact
later provider-source counterparts. That result is a locator reconciliation only. It
does not prove byte identity, recording identity, relevance, uploader ownership, or
that either collection is complete.

The linked [torrent announcement](https://www.reddit.com/r/HIMRFAM/comments/1pqdsxm/himr_streams_archive_722gb/)
also says its `YouTube Videos` directory contains some files absent from its bundled
Internet Archive copy and describes the old/new YouTube and Kick livestream folders
as the torrent's principal exclusive material. In the comments, the uploader says a
roughly 24-hour post-breakup stream was not captured because YouTube truncated the
VOD and it was deleted quickly. That is useful negative inventory evidence, not proof
that no other copy exists. The corpus therefore records “uploader reports missing”
rather than silently inserting a placeholder video or calling either archive
complete.

these records separate.

## Intake rule for every lead

1. Snapshot the public metadata response without rewriting the supplied URL.
2. Extract stable platform IDs, uploader/channel IDs, title, duration, and publication
   date as distinct metadata fields.
3. Reconcile against the existing catalogue before downloading media.
4. Mark copies as raw, reposted, edited, compilation, commentary, or unresolved.
5. Use copied captions or fan prose only to locate the underlying source.
6. Apply the [source and verification method](/wiki/archive/methodology/) before a
   discovered claim enters an article.
