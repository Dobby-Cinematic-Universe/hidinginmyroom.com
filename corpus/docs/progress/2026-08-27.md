# Corpus progress — 2026-08-27

## Strict media-local transcript projection lane

Migration 0029 and its application code now define a reviewed, append-only vertical
slice for three to five complete raw/contextual recording pairs. The manifest schema
pins exact media, source mapping, rank-700 public acquisition observation/import
receipt, pair, diff, and duration facts. The
identity transform accepts 0 ms normalized-parent disagreement and no more than 5 ms
normalized-recording metadata disagreement, with zero ASR overrun and no timestamp
repair.

Generated ordinary revisions deliberately use a null `rendition_id`: at admission,
the exact normalized audio inputs have no rendition, and the parent video's sole
rendition is stored only as projection evidence. Apply inserts the deferred child
graph before its
batch header and runs the same exact-row replay used by database validation.

The batch also seals the original UTF-8 manifest bytes and verifies their raw digest
without reopening the original path. Historical replay uses immutable acquisition and
lineage receipts, including the normalized artifact, its completed preprocess run,
and the exact completed preprocess import, not mutable current source access,
recording duration/canonical-key, or mapping-confidence projections. Exact media
content identity, source native identity, selected derivation/media-source mapping,
and parent-rendition identity are sealed; explicitly mutable catalog projections
remain correctable.

The v1 lane rejects a selected media-source row with a non-null source snapshot,
seals the preprocess producer's complete input/artifact graph, and requires both
source-ASR and preprocess runs to have completed no later than coordinate review.
Generated processing-run and revision/projection JSON is plan-bound and checked by
SQL, while an independent child-identity digest catches segment/word ID generator
drift during deep replay.

No reviewer was created or activated, no review was attested, no production manifest
was approved, and migration 0029 was not applied to a live database in this work.
Disposable tests cover reviewed fixture manifests only. The next human step is to
construct and inspect a real 3--5-recording manifest against a disposable current
catalog, then approve its newly generated digest if the pinned evidence is correct.
