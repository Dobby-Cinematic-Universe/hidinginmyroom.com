# Bounded private YuNet detector bridge

`yunet_face_detector.py` is a deterministic offline bridge from exact PNG frames to
the anonymous `frame_local_face_detections` contract consumed by
[`shot_local_face_tracker.py`](shot_local_face_tracker.py). It runs only the pinned
FP32 YuNet detector under an isolated OpenCV/NumPy runtime. It has no crop, SFace,
embedding, identity, active-speaker, catalog, network, or publication interface.

Revision `0.2.0` retains the synthetic-fixture profile and adds one narrowly bounded
`public_single_shot_pilot_only` profile. That profile is only for an already admitted
public source, one manually reviewed shot, and its complete dense 25 fps frames. The
adapter cannot prove public-source eligibility or review authorship, so those remain
separate packet evidence and `human_review_required` stays true. Sparse corpus frames,
machine-only scene-change candidates, private/member-only material, and multi-shot
real sequences remain out of scope.

## Closed input contract

The work order is governed by
[`schemas/yunet-face-detector-work-order.schema.json`](schemas/yunet-face-detector-work-order.schema.json).
Runtime validation is stricter than JSON Schema alone:

- `policy.material_scope` is either `synthetic_fixture_only` or
  `public_single_shot_pilot_only`. The latter requires exactly one shot and is subject
  to the same 64-frame bound, so the current 25 fps profile cannot exceed 2.56 seconds.
  Networking, embeddings, identity decisions, active-speaker decisions, and
  publication authority are disabled in both profiles.
- Python, the OpenCV and NumPy wheels and loaded extension binaries, OpenCV build
  information, the YuNet ONNX file, and its MIT license are pinned. Runtime import is
  restricted to the owner-private isolated module tree. OpenCV uses one CPU thread
  and OpenCL is disabled.
- Every PNG must be a resolved, immutable, owner-private regular file with one hard
  link. The adapter captures and hashes the exact bytes it later decodes. It rechecks
  every logical input before publication, so an atomic replacement cannot change the
  verified inference buffer and cannot survive the final integrity gate.
- Shot bounds are ordered, half-open, and non-overlapping. Each frame must map to
  exactly one declared shot, and every declared frame must be present at the exact
  40 ms cadence. Dimensions must remain constant within a shot and may reset only at
  the next shot.
- The bounded profile admits at most 64 shots, 64 frames, 64 detections per frame,
  16 MiB per PNG, 64 MiB of aggregate PNG bytes, and 1920×1080 pixels per frame.
- The output root must already be owner-private and cannot be inside repository
  `src/`, `public/`, `dist/`, or `.git/` paths. Existing results, symlinks, writable
  private inputs, hash drift, unknown keys, ambiguous shot assignments, and invalid
  model geometry all fail closed.

The OpenCV Zoo model is fixed to commit
`47534e27c9851bb1128ccc0102f1145e27f23f98`, artifact SHA-256
`8f2383e4dd3cfbb4553ea8718107fc0423210dc964f9f4280604804ed2552fa4`,
and the official parameters `score_threshold=0.9`, `nms_threshold=0.3`, and
`top_k=5000`. A raw detector score is explicitly
`raw_model_score_not_calibrated_probability`; this bridge chooses no operating
threshold beyond the upstream detector setting and makes no probability claim.

## Output and tracker handoff

The generated `detections.json` uses the existing strict
[`shot-local-face-detections.schema.json`](schemas/shot-local-face-detections.schema.json)
shape. Zero, one, or multiple detections are preserved for each frame. Detections are
sorted deterministically by descending raw score and then geometry; IDs derive from
the frame, ordinal, and exact values. Each detection retains pixel box geometry, five
landmarks, raw score, and the below-64-pixel-width flag.

Before sealing, the adapter round-trips both JSON documents, runs the tracker's strict
semantic validator over the exact detections, and runs a closed semantic validator
over the result receipt. Repository tests additionally validate the generated bytes
against both Draft 2020-12 schemas. `detections.json` and `result.json` are flushed and
sealed `0400`; the staging directory is flushed and sealed `0500`; Linux
`renameat2(RENAME_NOREPLACE)` is the atomic success boundary. There is deliberately no
fallible work after rename. The adapter therefore claims deterministic process-level
publication and no overwrite path, but does **not** claim power-loss durability for
the final directory entry because it does not perform a fallible parent-directory
`fsync` after that boundary.

Every artifact keeps embeddings absent, identity and active-speaker states unknown,
labels/scores null where applicable, all decisions false, publication false, and
human review required. Detector output can route private review; it cannot name a
person or establish that two boxes show the same person.

## Usage

Start from
[`examples/yunet-face-detector-work-order.example.json`](examples/yunet-face-detector-work-order.example.json),
replace every path and pin, and use a private ignored result root:

```sh
pipeline/bin/yunet-face-detector \
  --work-order /absolute/private/path/work-order.json \
  --dry-run

pipeline/bin/yunet-face-detector \
  --work-order /absolute/private/path/work-order.json
```

Validate tracked and generated contracts with:

```sh
python3 scripts/validate-json-contracts.py \
  --validate pipeline/schemas/yunet-face-detector-work-order.schema.json /private/work-order.json \
  --validate pipeline/schemas/yunet-face-detector-result.schema.json /private/result.json \
  --validate pipeline/schemas/shot-local-face-detections.schema.json /private/detections.json

python3 -m unittest pipeline.tests.test_yunet_face_detector -v
```

The adversarial suite covers unknown keys, input hash drift, writable/symlinked/
hard-linked frames, atomic model and frame replacement, overlapping and ambiguous
shots, incomplete or mistimed dense sequences, dimension changes, invalid and
non-finite detector output, zero/multiple detection preservation, tracker contract
compatibility, release-path and output-symlink rejection, existing-output refusal,
and an injected final-path race.

## Private pilots

The ignored 2026-08-28 packet contains four procedurally drawn PNGs across two shots.
The real pinned OpenCV/YuNet runtime completed offline with one CPU thread and emitted
four frame rows with zero detections. Its artifact then passed unchanged into the
fixed shot-local tracker, which correctly emitted four frame rows and zero tracks.
This is useful negative-path and interface evidence only: a procedural drawing with no
detection says nothing about YuNet recall, precision, tracking quality, real-person
identity, active-speaker performance, or ADR 0007 Gate 3. The focused fake-runtime
fixture separately proves that zero and multiple rows are preserved and that positive
geometry can flow into distinct shot-local tracks; it is not model-quality evidence.

The separate ignored real-media packet uses one two-second, manually inspected shot
from an admitted public main-channel source. All 50 dense frames traversed the pinned
one-thread detector and unchanged shot-local tracker. YuNet emitted 20 anonymous
detections across 20 frames, with 30 zero-detection rows; the development tracker
recipe routed them into four shot-local tracks. This demonstrates only runtime and
contract continuity on real bytes. It does not measure recall, precision, tracking
quality, identity continuity, active-speaker quality, or Gate 3, and it creates no
publication authority. Exact frames, boxes, landmarks, raw scores, and track geometry
remain owner-private.

Any further real-media run still requires exact dense frame and shot lineage. The
existing 100-second sparse DN0 frames and unreviewed machine scene-change candidates
remain expressly insufficient.
